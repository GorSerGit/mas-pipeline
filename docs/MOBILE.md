# MOBILE: standalone Container3 engine inside mas-pipeline

API unchanged: GET /health, POST /work. Request retains run_id (UUID), task,
context, contract (including openapi). Orchestrator does not change.

## What changed

services/mobile contains Container3's mobile_agent.py, android_build.py,
snippets.py and snippets/android/*.md. Generation follows depends_on layers;
each file sees declarations of its dependencies. Android generation runs
assembleDebug and testDebugUnitTest, then repairs compiler/test failures.
JSON parsing and GenerationError live in generation_utils.py. Container3's
orchestrator, main, agent_client, coder_main and stubs are not included.

Pipeline main.py remains the API/Tester adapter. It persists generated source
only after successful internal build and sends it to tester /validate.
Tester alone can approve and return zip_path. Build infrastructure errors and
exhausted internal retries return status=failed. Tester feedback is included
in the next generation. Regeneration replaces the complete source tree,
preventing obsolete files from remaining in a corrected project.

LLM_URL (OpenAI-compatible base URL ending in /v1), LLM_API_KEY and LLM_MODEL
come from pipeline environment. Trailing slash is accepted. TLS verification
is enabled. No source Container3 .env or credentials are copied.

Dockerfile carries JDK and Android licenses; Gradle distributions, Android SDK
and Gradle home are cached in the mobile-cache volume at /cache. SDK/platforms
and dependencies are downloaded on first use: internet access is required.
No KVM is needed for compilation or JVM unit tests.

## Build and run

From the mas-pipeline directory, use your existing .env:

```sh
docker compose build mobile
docker compose up -d mobile
docker compose exec mobile python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/health').read().decode())"
docker compose exec -e LLM_URL=http://example.test/v1 mobile python -m unittest discover -s tests
```

The last command mocks LLM/build for unit tests, except test_snippets_build,
which performs an actual Gradle build when Android prerequisites are present.
To run only offline engine tests: append `-p test_mobile_agent.py`.
The service listens on port 8000 inside the Docker network. Existing optional
port mappings remain in docker-compose.ports.yml.

## Settings

- MAX_REPAIR_ATTEMPTS=3: outer generation/Tester attempts.
- MOBILE_FIX_ROUNDS=5: repair rounds inside each generation.
- MOBILE_BUILD_TIMEOUT=1800: timeout in seconds per build.
- MOBILE_COMPILE=1: required by /work; service refuses to approve unbuilt output.
- MOBILE_BASE_URL=http://10.0.2.2:8080/: generated Android application's backend
  URL, not the agent URL. Configure an address reachable by the target emulator
  or physical device. 10.0.2.2 means the emulator host; it is not automatically
  the backend generated by the pipeline.

## Runtime testing and activation

MOBILE is enabled by default (`DISABLED_ROLES=` in .env and Compose).
Tester probes /dev/kvm on the Docker daemon host using its own existing image.
If the device is missing, Android runtime/UI tests return status=skipped,
skip_reason=no_kvm and a Russian explanation. No emulator image is needed for
this skip. Docker daemon/probe failures and permission errors are real errors.

Skipping requires successful assembleDebug and testDebugUnitTest evidence
from MOBILE. Tester archives the source; MOBILE forwards status=skipped to
Orchestrator without another generation attempt. Final ZIP includes
 test-skips.json; Android-only criteria are marked skipped in coverage.json.
The run report and progress events explain the missing KVM. No runtime test
is reported as passed. With KVM present, the existing emulator path executes.
Missing runner image and actual build/startup/test errors still fail.

Rebuild and recreate updated services from the project root:

```sh
docker compose up -d --build mobile tester orchestrator
```
